# Port 1.0.0.3663 -> 1.0.0.3732 (2026-11-19)

Steam updated the game on 2026-11-19 at 02:08, during the user's PC restart (PE 0x6AFDC0CF, SizeOfImage 0x13C7E000,
326,610,840 bytes; archived as build/exe-archive/CrimsonDesert-1.0.0.3732.exe). Found at 12:40 in pp35's logs: every
step after `static` failed with "Co-op+ is off: this mod was made for game version 1.0.0.3663, not 1.0.0.3732". The
posted build 9e85b891 is off on the new game, as designed; testers were told at 12:42 in #play-testing-feedback.

A much smaller update than 3576 -> 3663:

| What | 3663 -> 3732 |
|---|---|
| Functions (.pdata) | 224,300 -> 224,326; 221,665 paired (98.8%) by fmap |
| Code section | 0x5612000 -> 0x5617000 bytes; names scrambled again (code ".xpdata", protection ".text1" 0x7ACB000..0x137DB000) |
| Message numbers | 1179 -> 1179, NONE changed |
| Functions our code names | every one the same masked code (the byte patterns changed only in relative operands; whole-body checksums: same instructions) |
| Struct fields | 88 displacement shifts in the 606 functions we name: almost all switch-table bases; real field moves (+1, +16, -256) in 7 functions, none of them a field our code reads |
| Mid-hook sites | native 260 clean; nothing to port by hand |

## Steps (tools in build/port3732, kept in tools/native-port/port3732; p73*.py in tools/native-port)

1. `fmap.py` (the function map), `troc63.py` (message numbers, by RTTI name: 0 changed).
2. `p73.py scan|scan2|judge native|layer` (made from p63.py by make_p73.py; apply / heads / inline refuse a second run).
   Judge left 18 native + 13 layer addresses: jump stubs into the protection (a `jmp rel32` with no .pdata entry),
   confirmed by every old caller's mapped call now targeting the guess (`thunk73.py`) or by the one vtable slot that
   points at them (7-8 neighbouring slots agree); two switch tables (same entries + the function's shift); the rest
   computed (`kTrocInstancesEnd` = begin + the same size, the frame clock = flag + 0x34 / + 0x3C). `p73_hand.py`.
3. `p73.py apply` (776 native literals in 73 files, 140 layer in 24), `heads` (74 native arrays + 3 layer, all
   displacement-only: `shape73.py`), `inline` (4).
4. `pins73.py` + `pins73b.py`: inside the protection (`prot73.py`: the k-th call to the mapped callee; the three timer
   returns by the 12-16 bytes before them; the menu's two protected functions by their masked pattern), the build
   stamps, the protection's range and name (".text1"), the layer table offsets_3663.h -> offsets_3732.h (build_3732).
5. `fix73.py`: numbers `apply` rewrote although they are NOT addresses (see below).
6. `body73.py`: guest_sched_load's whole-body fnv checksums (the same code, new bytes).
7. `tests73.py` (30 literals in the native unit tests) + 3 hand pins. Unit tests: 30 of 90 executables fail, the same
   count as before the port.
8. `mapcheck.py` (native 1061 inside the paired function, 2 outside: an interaction id and a 2976 table entry),
   `dispsurvey.py` / `dispcand.py`, `midsites.py`, `stackdiff.py` (all with p73's map now: they imported p63 before).

## The mistake that mattered: apply rewrote game DATA that looks like an address

Any hex literal of 5+ digits below the protection's start is a candidate, and a number that happens to lie inside a
paired function is "mapped". Caught by `review73.py` (every rewrite with its line, the ones whose line does not read a
game address printed) and by mapcheck's "outside the paired function":
- interaction keys / stat ids: the catch rule's 0xF42BE / 0xF42CD (it would have stopped catching animals again), the
  shop interaction 0x000F4321 (trade_probe), the shop dialog group 0x000F4440, the HP stat 0x000F4240 (7 layer files:
  enemy scaling, hits, capture), the photo-mode id 0xCB0A77;
- masks and sizes: 0xFFFFFF (the Steam friend-join app id check, photo mode), 0x1000000 (fake id ranges), 0x0010F000,
  our own DLL's size 0x2065780, a code-range bound 0x4A00000, a bit mask 0x100004 (I had even mapped this one by hand);
- one range end (0x7160000) whose start was skipped.
All put back (fix73.py). For the next port: run review73.py right after apply and BEFORE building; better, teach the
scanner to skip `uint32_t`/`uint64_t` constants whose names say Id / Key / Stat / Mask / Bit / Interaction.
